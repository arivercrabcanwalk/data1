# 2026-07 全量复盘体系重建

本目录用于把“市场情绪 → 题材主线 → 板块生命周期 → 个股地位 → 预期差 → 盘中确认 → 交易 → 盘后复盘 → 规则更新”完整落实后，再进行7月逐日前向回测。

## 硬性原则

1. 正式回测只允许读取 `2026-07/**/minute1.parquet`、同日 `daily_stock_status.parquet` 与本目录中经过 PIT（point-in-time）审核的外部公开信息快照。
2. 任何外部信息必须记录 `source_url / published_at / available_at / captured_fact / evidence_type`，不得用月底总结倒灌月初。
3. T 日盘后形成的复盘结论、题材阶段判断、模式升降权，只能从 T+1 起生效。
4. 不能因为已知某笔历史交易盈亏而修改该交易之前的参数；规则修改必须有当时已经出现的重复样本、市场结构证据或事先定义的触发条件。
5. 23个交易日任何一天缺少必需数据，`readiness_gate.py` 必须阻止正式回测启动。
6. 不追求把7月调成高收益答案；7月用于验证复盘体系能否因果地学习。后续真正泛化评估必须用未参与设计的月份。

## 完整体系

### A. 市场情绪层
字段至少包含：涨停、跌停、炸板、封板率、最高板、连板数、1进2、2进3、高标晋级率、昨日涨停溢价、昨日连板溢价、大面数量、上涨/下跌家数、成交额、主板/20CM赚钱效应。最终映射为：冰点、修复、升温、高潮、降温、退潮。

### B. 题材主线层
每个题材记录：催化、首次可见时间、涨停家数、强势股数、最高板、梯队完整度、炸板率、亏钱效应、板块成交额、持续性、扩散速度、回流次数、主线占比、生命周期（Day0/启动/确认/发酵/高潮/首次分歧/修复/二次分歧/退潮）。

### C. 市场地位层
每只候选股每天只能被标注为以下角色之一或明确为未知：总龙头、主线龙头、容量中军、弹性核心、前排、补涨、切换先锋、跟风、杂毛。核心不等于“涨幅强”，必须包含辨识度、带动性、梯队地位、题材地位与资金容量。

### D. 带动性层
使用 GitHub 全市场1分钟数据计算 Lead-Lag：个股关键拉升后的5/10/20分钟，同题材股票上涨广度、平均收益、涨停/触板数量是否同步提升。用于区分“它带板块”与“它只是跟板块”。

### E. 交易模式层
首版只允许：
- 龙头主升
- 核心第一次大分歧后的转一致
- 核心弱转强
- 龙头打开空间后的补涨
- 高位严重亏钱效应后的低位切换
- 冰点后修复先锋
- 容量核心趋势回踩
- 无清晰赚钱效应时空仓

每种模式必须声明：适用情绪、适用题材阶段、允许角色、禁止角色、盘前预期、盘中确认、入场、失效、退出、仓位和样本升级条件。

### F. 预期系统
每天收盘生成次日四情景：超预期 / 符合预期 / 低于预期 / 切换。次日只能把实际走势与昨晚已封存的预期比较，形成 expectation gap。

### G. 错题与复盘层
每笔交易支持错误标签：FOMO_CHASE、REVENGE_TRADE、STYLE_DRIFT、LOW_RANK_FOLLOWER、LATE_CYCLE_ENTRY、NO_THEME_SUPPORT、EXPECTATION_NOT_CONFIRMED、WRONG_ROLE、WRONG_CYCLE、CORRELATED_BETS、EXIT_TOO_EARLY、EXIT_TOO_LATE。

复盘流程固定为：Observation → Hypothesis → Sample → Rule。单笔亏损不能直接修改规则；重复样本达到门槛后才允许降权/暂停/升级。

## 完整性门槛
正式回测前，23个交易日必须同时拥有：
- market_snapshot
- theme_snapshot
- ladder_snapshot
- role_snapshot
- expectation_snapshot（首日允许 cold_start）
- source_evidence

`readiness_gate.py` 输出 READY 才允许运行正式回测。
