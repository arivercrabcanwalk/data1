# 7月历史重建：数据缺口与使用边界

## 1. 7月1日冷启动

价格执行层被限定为只读取 GitHub `2026-07`。因此 2026-07-01 没有 2026-06-30 的本地昨收，无法严格计算相对昨收涨跌、竞价高低开和涨跌停价。

处理：7月1日只复盘，不交易；7月1日收盘信息从7月2日开始生效。不借用6月价格补齐。

## 2. 603580 艾艾精工

公开市场资料在7月17日/20日前后仍将其列为高位辨识度或负反馈标的，但本地对应交易日分钟数据覆盖校验发现缺失。

处理：保留在历史认知层作为市场高标/负反馈锚；通过 `role_tradeability_overrides.csv` 将需要执行的日期改为 observation-only。绝不使用外部价格替代本地成交。

参考：https://www.cls.cn/detail/2430973

## 3. 003032 传智教育

公开资料确认7月29-30日其连续涨停并成为AI应用/教育方向高辨识度标的，但 GitHub 本地分钟数据在需要执行的7月30、31日未覆盖该代码。

处理：保留为历史题材核心观察锚，但本地不可执行。7月30的可执行同方向核心使用7月29日已公开的巨人网络、恺英网络；7月31使用7月30日早盘已公开且到收盘前已经可知的普联软件、恒锋信息、巨人网络、恺英网络、福石控股。所有替代角色仍须通过本地分钟存在性和状态表门禁。

参考：
- https://www.cls.cn/detail/2439813
- https://www.cls.cn/detail/2440914

## 4. 688825 长鑫科技

公开和交易所资料确认其2026-07-27新上市。新股首日/初期不进入普通超短模式样本。

处理：仅保留为半导体/存储产业链容量与情绪观察锚，`tradable_next_day=0`，不参与普通模式执行。

参考：https://www.sse.com.cn/disclosure/announcement/listing/ipo/c/c_20260724_10826610.shtml

## 5. 互联网题材信息的点时边界

首版不构建“假装完整”的分钟级新闻流。原因是只收集少量后来显眼的盘中报道会形成选择偏差。

统一规则：
- 当日收盘复盘/当日已经公开的题材事实，最早下一交易日进入计划。
- `source_publish_at > decision_at` 的信息绝对不可使用。
- 月度总结、后来的概念成分、后来出现的产业链标签不得倒灌。
- 个股历史题材角色来自当日/此前可见公开资料；通用产业链表只描述结构，不维护静态个股成员。

## 6. 互联网资料的非穷尽性

无法证明已覆盖字面意义上的“全网所有资料”。当前目标是覆盖每个7月交易日的主要盘后结构，并对可交易题材提供至少一个有来源的核心关系，再由 GitHub 全市场分钟数据负责执行验证。

因此：
- 复盘库可以用于历史点时实验；
- 不能把它描述成交易所官方题材数据库；
- 回测收益不能被解释为两位网络交易者本人策略的真实收益；
- 任何后续资料补录都必须记录生效日期，不允许改写已经发生的7月决策。
