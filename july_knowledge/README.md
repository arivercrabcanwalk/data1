# 2026-07 短线复盘知识层（先知识、后回测）

本目录是 2026 年 7 月正式回测之前的知识层。目标不是调参追求历史收益，而是把“市场环境 -> 题材主线 -> 个股地位 -> 预期差 -> 模式 -> 盘后复盘 -> 次日更新”完整落地成可审计数据。

## 绝对约束

1. 正式回测前必须先完成知识层构建和审计。
2. 行情事实只读取仓库 `2026-07/**/minute1.parquet` 与同日 `daily_stock_status.parquet`。
3. 网上资料只负责题材、催化、连板语境、主线/龙头候选等行情文件本身没有的语义信息。
4. 收盘复盘信息最早 T+1 生效；盘后才发布的消息不能用于 T 日盘中。
5. 历史网页中后来加入的“明日回验、相似日期、未来统计、AI事后总结”等字段禁止进入信号层，只允许进入审计层。
6. 不允许用 7 月底结果回改 7 月初标签、阈值或规则。
7. 不允许把单一网站对题材/涨停口径的结论当作绝对事实；必须保留来源、抓取时间、原始文本哈希和冲突记录。
8. 任何无法证明当时可获得的信息，`trade_eligible=false`。

## 数据分层

- `raw_web/`：历史网页快照，仅用于溯源。
- `generated/market_daily.csv`：由 GitHub 1 分钟数据计算的市场广度/成交/涨跌统计。
- `generated/source_daily.csv`：网页来源原始日统计，不强行统一口径。
- `generated/theme_daily.csv`：逐日题材强度、主线、催化、龙头候选。
- `generated/theme_membership.csv`：逐日股票-题材映射。
- `generated/leader_ladder.csv`：总龙/主线龙/容量核心/弹性核心/补涨/切换先锋/跟风候选。
- `generated/source_audit.csv`：不同来源和 GitHub 行情之间的冲突与可用性审计。
- `generated/expectation_book.csv`：只用 T 日及以前信息生成的 T+1 情景预期。
- `generated/knowledge_manifest.json`：构建版本、输入哈希、有效时间规则。

## 地位不是“涨得多”

核心地位至少由以下证据共同决定：

- 所属题材是否是主线/次主线
- 连板高度和持续性
- 同题材内相对强度
- 成交额/容量
- 封板或修复时点
- 同题材跟随数量和带动性（leader move 后 5/10/20 分钟板块响应）
- 负反馈时的抗跌性
- 题材生命周期位置

因此“强势股”与“市场核心”在数据层明确分开。

## 模式定义（研究版，不直接交易）

### 龙头主升
市场处于修复/升温/主升，题材持续增强，核心地位明确。只研究主线核心，不拿后排跟风替代龙头。

### 补涨
前一主线仍有赚钱效应，龙头打开空间，但低位出现同题材或同逻辑扩散。若原周期已经进入明显主跌，则不能再标记为补涨。

### 切换
旧周期已出现显著亏钱效应后，新共性/新题材在低位试错并逐渐聚焦。切换必须与旧亏钱共性有明显差异。

### 冰点试错
市场处于冰点或冰点后首次修复，仅允许极小风险预算观察率先逆势形成带动的核心候选。

### 核心弱转强
前一日已具备核心身份；次日竞价/开盘弱于预期，但在指定时间窗内主动转强，同时题材和市场确认改善。普通强股反抽不算。

### 分歧转一致
前一日核心发生可解释分歧；次日抛压消化后重新获得题材跟随和市场认可。必须有“地位 + 板块反馈”两层确认，只有价格V形反弹不算。

## 错误标签

`NO_THEME_SUPPORT`、`LOW_RANK_FOLLOWER`、`LATE_CYCLE_ENTRY`、`FALSE_REPAIR`、`NO_LEADERSHIP`、`EXPECTATION_NOT_CONFIRMED`、`FOMO_CHASE`、`REVENGE_TRADE`、`STYLE_DRIFT`、`OVERSIZED`、`EXIT_RULE_VIOLATION`、`DATA_NOT_PIT`。

## 迭代纪律

每日更新只能走：

`Observation -> Hypothesis -> Sample accumulation -> Rule change`

禁止：

`Loss -> tune threshold until past trade disappears`

规则变化必须写入带日期的变更日志，并从下一交易日生效。单笔亏损默认只记录，不立即修改规则；同类错误达到预先规定的样本门槛后才允许降权/暂停。
