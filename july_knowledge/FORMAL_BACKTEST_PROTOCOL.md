# 正式7月前向回测协议（知识层通过后才能执行）

本文件提前冻结未来正式回测的时间顺序，防止知识层完成后再根据7月结果改流程。

## 每个交易日的时间箭头

### T-1 收盘后
读取 `daily_review_book`、`theme_rank_daily`、`leader_role_candidates`、`profit_loss_effect`，生成并冻结 `expectation_book`。只允许使用截至 T-1 已公开且通过点时审计的语义信息，以及截至 T-1 的 GitHub 行情。

### T 盘前
只读取 T-1 冻结预期和当日盘前可获得信息。若未来没有可靠的逐分钟新闻时间戳数据库，正式7月回测默认**不使用T日临时新闻文字**，避免事后把午后消息倒灌进早盘。

### T 盘中
行情只能逐分钟向前推进。任何分钟信号必须在该分钟完全结束后才能确认，最早下一分钟 open 成交。禁止使用确认分钟 close 作为可成交价。

交易候选必须先满足：
`市场阶段允许 -> 题材在T-1高置信池/盘中已被允许确认 -> T-1已有地位候选 -> Playbook前置条件 -> 盘中确认 -> 风险预算`

普通全市场强势股不能绕过题材/地位层直接进入候选。

### T 收盘
先结算账户，再执行复盘。T的复盘、错误分类和模式统计只能改变 T+1 及之后的规则权重，不能影响T已经发生的交易。

## 成交真实性

正式回测必须纳入：A股T+1、100股整数手、手续费、印花税、双边滑点、ST/新股/停牌、各板块涨跌停规则、涨停无法买入/跌停无法卖出的可执行性。若盘口深度缺失，不能声称精确模拟大额冲击成本；需设置保守滑点并报告敏感性。

## 风险框架

- 不设置“为了达到目标收益”而倒推的杠杆。
- 模式级单笔风险预算预先冻结。
- 总仓位由市场阶段与账户回撤共同限制。
- 回撤保护必须有预先定义的恢复条件，避免“跌破某线后永久0仓”的死锁。
- 高相关题材/同一Playbook同时持仓需要相关性上限，避免伪分散。

## 每日学习规则

`单笔失败 -> 记录`

`同一错误/模式连续出现2个同类样本 -> 观察标记`

`达到预先声明的最低样本门槛 -> T+1降权/暂停候选`

`更高样本量 + 跨环境一致 -> 才允许规则升级`

所有变化必须落入 `rule_change_log.csv`，且 `effective_date > decision_date`、`applies_retroactively=false`。

## 禁止事项

- 先跑完整7月再回头选择最赚钱Playbook。
- 看7月最终赢家后修改题材/龙头标签。
- 依据某笔亏损调整阈值直到该笔交易消失。
- 使用文章中后来出现的“明日回验/相似日期/未来统计”。
- 把月底知道的热点归因当作月初已知。
- 用8月或更晚行情帮助选择7月参数。

## 正式交付

正式回测完成后必须同时给出：月收益、最大日终/分钟回撤、胜率、Profit Factor、平均R/中位R、每个Playbook表现、每个市场阶段表现、每天权益、每天复盘卡、每次规则变化、每一笔交易的买卖时间/价格/仓位/题材/地位/预期/触发/退出/MFE/MAE/错误标签。

如果结果亏损，原样报告；不能再用同一7月数据反复优化后冒充新的独立验证结果。
